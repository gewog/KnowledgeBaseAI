1 Что делает система, основная идея?

Идея: система представляет собой высоко-адаптивную и персонализируемую платформу для обучения, которая отходит от традиционных линейных учебных программ (Область знания: тема 1 -> тема 2 -> тема 3 и т.д.) и в основе которой лежит идея определенного (ака детерминированного) графа (Knowledge Graph). Система объединяет в себе концепцию графов и семантическую возможность LLM/PAG – система понимает смысл слов, а не просто их буквы (RAG — дает информацию ЛЛМ для ответа). Граф – главное хранилище.

Система подразумевает подтвержденные факты: Каждый элемент в графе привязан к источнику —фрагменту документа. Система не генерирует информацию без опоры на материалы.

Neo4j (The Brain): хранит топологию знаний (карта связей между темами-сущностями), онтологию (правила устройства карты) (Concept, Skill, Error) и связи (PREREQ, BASED\_ON).

Qdrant (The Semantic Layer): Отвечает за векторный поиск и RAG. Векторный поиск отличается от обычного тем, что векторный поиск ищет по смыслу.

PostgreSQL (The Backbone): Хранит пользователей, метаданные Proposals, историю задач и Audit Log.

В системе онтология (устройство карты) определяет три базовых сущности:

Concept — теоретическая идея (например, «производная»),

Skill — умение применить знание («находить производную многочлена»),

Error — типичная ошибка («путает производную суммы и произведения»).

И правила связей: например, Skill может иметь связь BASED\_ON с Concept, а Error — связь RELATED\_TO с Skill.

Что делает:

Система в своей реализации решает (как минимум) следующие задачи:

\- Строит индивидуальные маршруты обучения на основе уровня знаний, уверенности и сложности материала. Можно учиться не по порядку, а по связям между темами.

\- Определяет оптимальную последовательность обучения, используя алгоритм A\*.

\- Обеспечивает наличие визуализации и аналитики: наличие инструментов для исследования графа, построения дорожных карт и оценки прогресса.

\- Поддерживает генерацию контента, семантический поиск (RAG) и объяснение связей между узлами графа (объяснения материала от ии).

\- Обеспечивает безопасность, так как все изменения проходят через систему **Proposals** (Draft → Proposal → Validation → Commit). Иными словами, напрямую редактировать базу нельзя. Любое изменение проходит этапы: черновик → предложение → проверка → контроль целостности → публикация.

Конечным пользователем данного проекта бесспорно можно назвать обучающегося всех видов (школьник, студент и т.д.). Данный сервис позволит ему построить персональную дорожную карту по изучению математики, а также получать объяснения от ии. Но также этот сервис может стать полезным для образовательных учреждений и платформ: выявление пробелов в знаниях с помощью сервиса, генерация и оптимизация учебных планов.

5 Что по архитектуре (потоки данных, выделение ключевых компонентов и их ролей)?

Потоки данных (как я их поняла):

1.  Пользователь или скрипт загружает данные → load\_data.py → PostgreSQL.
2.  Данные синхронизируются с графом → push\_to\_neo4j.py → Neo4j.
3.  Векторные встраивания генерируются и сохраняются → Qdrant.
4.  AI-агент (OpenAI) генерирует контент → generate\_subject\_openai\_async → Proposal System.
5.  Proposal проходит **валидацию** → commit\_proposal → Neo4j (финальный коммит).

Адаптивное обучение

1.  Пользователь проходит тест → результаты фиксируются в PostgreSQL.
2.  Roadmap Planner анализирует прогресс → plan\_route (построение оптимального маршрута) → возвращает оптимальный маршрут из Neo4j.
3.  Frontend визуализирует маршрут с помощью vis-network.

Семантический поиск (RAG)

1.  Запрос пользователя → Qdrant ищет релевантные фрагменты.
2.  LLM (OpenAI) генерирует ответ с контекстом → возвращается пользователю через assistant.py (вроде бы).

6 Анализ качества: замечания по читаемости, архитектурные и логические риски, где возможны проблемы при росте нагрузки (насколько я могу судить)

Плюсы:

\- Чёткое разделение на модули.

\- Использование Pydantic для валидации.

\- Документация в виде docstrings.

Минусы:

\- Дублирование логики в скриптах (scripts/) (возможно)

\- Отсутствие единообразия в обработке ошибок.

Архитектурные и логические риски:

Зависимость от внешних сервисов: OpenAI/Claude API могут быть недоступны (уже для некоторых) или дорогостоящи.

Сложность масштабирования: Neo4j и PostgreSQL могут стать проблемой при росте нагрузки.

Возможные проблемы при росте нагрузки (с бд):

Neo4j: Графовые запросы могут замедляться при большом количестве узлов.

PostgreSQL: Метаданные и история изменений могут требовать партиционирования или решардинга.

Redis: Очереди могут перегружаться при большом количестве фоновых задач.
